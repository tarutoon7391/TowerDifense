# 迷宮の守護者（fantasy-maze-td）

ブラウザで遊べるファンタジー風・迷路建築型タワーディフェンス。
Node.js + Express + Canvas 2D。ゲームロジックは `shared/` に完全分離し、
ブラウザと Node の両方から同じコードを import できる（将来のサーバー権威化を想定）。

本番: https://web-production-08d0a0.up.railway.app （GitHub main への push で自動デプロイ）

## 構成

```
server.js            Express: public/ と shared/ を静的配信（PORT 未設定時 3000）
shared/              ゲームロジック（ESM。DOM/Math.random/Date.now を使わない）
  config.js          ステージ・建築80種・敵14種・ウェーブ・変異・反応・魔法・経済の全パラメータ
  rng.js             シード付き疑似乱数（mulberry32）
  state.js           JSON 化可能なゲーム状態の生成（地形をグリッドに展開）
  pathfinding.js     ゴールからの BFS（床は通行可、転送門は隣接扱い）・到達判定・表示用経路
  towers.js          レベル別ステータス・Lv3 分岐・強化費用の計算
  buffs.js           支援バフ（最大値が有効）・隣接シナジー・地形相性・警鐘・経済修正値
  commands.js        placeTower / sellTower / upgradeTower(分岐) / toggleBridge / startWave / callNextWave / castSpell
  simulation.js      step(state): 1tick = 1/30 秒 進める
public/              描画・入力（素の JS + ESM、外部アセットなし）
  js/main.js         ステージ選択・ドラフト・日替わり・リプレイ・ジャンルタブ・ループ・HUD
  js/renderer.js     Canvas 2D 描画（地形・床・塔・兵士・敵・弾・演出・効果範囲・ミニマップ）
  js/input.js        Pointer Events（マウス/タッチ）→ コマンド呼び出し / ドラッグ配置 / 魔法の着弾指定
test/                node --test によるユニットテスト（66件）
agent.py             Claude Agent SDK によるレビュー用スクリプト（ゲーム本体とは無関係）
```

## ゲーム内容

### ステージ（4面・順番に解放。`?all=1` で全解放）

| # | 名前 | マップ | ウェーブ | 特徴 |
|---|------|--------|----------|------|
| 1 | 草原の門 | 20×12 | 10 | 高台あり。基本の迷路づくり |
| 2 | 渓谷の道 | 22×13 | 12 | 岩の谷。スライム・コウモリ・骸骨兵・破城槌オーガ |
| 3 | 凍てつく湖 | 24×14 | 14 | 湖を迂回する長い道。トロル・暗黒騎士・盗賊 |
| 4 | 魔王城 | 26×16 | 16 | 岩と水と高台。ネクロマンサー、11ウェーブ目と最終ウェーブに魔王（到達で即敗北） |

- 3ウェーブ目以降はシードから決まる**ウェーブ変異**（重装・巨大化・疾走・大群・呪われた）が付く。偵察気球があると事前に分かる
- ステージ選択で「今日の迷宮」（日替わりシード）と「ドラフト」（各ジャンル3候補から1つずつ持ち込む）を選べる
- クリア時は残ライフで★1〜3。リプレイコードをコピーして共有でき、ステージ選択画面で再生できる

### 建築（5ジャンル・80種。石壁以外は3段階強化、一部は Lv3 で分岐）

画面右のタブでジャンルを切り替える（Tab キー、1〜9・Q/W/E で選択）。

**近距離（14）** 茨の壁 / 槍兵の櫓 / 火炎放射器（炎）/ 剣闘士の塔 / 聖光の祭壇（聖）/ 氷柱の結界 / 衝撃槌（砕き）/ 竜の火口（炎）/ 処刑台 / 散弾の櫓 / 大樹の守り手 / 鎖の塔 / **兵舎・騎士団**（通路に兵士を配置して足止め）

**遠距離（13）** アーチャー塔（Lv3: 連射弓/狙撃弓）/ 弩兵の塔 / 風の弩 / バリスタ / 連弩 / 爆炎の投石台（Lv3: 榴弾/焼夷弾）/ 魔導砲 / 雷の尖塔（Lv3: 稲妻の嵐/雷帝の一撃）/ 月光の弓 / 迫撃砲 / 狙撃手の塔 / 流星の塔 / **竜の巣**（1基限定）

**支援（14）** 軍旗 / 見張り塔 / 照明塔 / 戦太鼓 / 鍛冶屋 / 砥石台 / 魔力の泉 / 祈りの祠 / 賢者の塔 / 占星台 / 司令塔 / 英雄像 / **警鐘**（踏まれると周囲の塔が一時強化）/ **禁断の祭壇**（攻撃2倍・毎ウェーブ ライフ−1）

**妨害（12）** 泥沼の呪具 / 氷の魔導塔（Lv3: 凍結/吹雪）/ 毒の祭壇 / 網投げ台 / 呪いの塔 / 弱体の瘴気 / 幻惑の鏡 / 吹雪の塔 / 疫病の祭壇 / 凍結の杖 / 腐食の霧 / 重力の塔（飛行を着地させる）

**特殊（27）** 石壁 / 鉄壁（壊されない）/ 桟橋（水を陸地に）/ 発破（岩を砕く）/ 泥濘の床・氷床・聖域の床・油溜まり（敵が通れる床）/ 落とし穴・地雷（罠）/ 転送門（2基で1組）/ 跳ね橋（開閉で経路を変える）/ 門柱 / 金鉱 / 市場 / 魔法の苗木 / 賞金首の掲示板 / 偵察気球 / 祈りの泉 / 商人の宿（壁は全額返金）/ 練兵場 / 錬金炉 / 宝物庫 / 魔力炉（魔法: メテオ・全体凍結・修復）/ 悪魔契約 / 賭博場 / 王の玉座

**仕組み**
- 支援は範囲内の塔に効き、同じ効果は重複せず最大値だけ有効。隣接シナジー（投石×氷＝蒸気爆発、雷×聖＝浄化 など）と地形相性（高台で射程+1、水辺で減速強化）もある
- 状態反応: 油まみれ＋炎＝引火爆発、気絶＋砕き＝砕け、毒＋聖＝浄化
- スロウは強い方が優先。押し戻された敵はしばらく押し戻されない
- 売却は投資額の50%（商人の宿で70%、壁は100%）。ウェーブ中は次のウェーブを前倒しで呼べる（残り敵1体につき+3）

## ローカル起動（Windows PowerShell）

```powershell
cd $env:USERPROFILE\Desktop\fantasy-maze-td
npm install
npm test
npm start
# ブラウザで http://localhost:3000 を開く
```

## 操作

- 左クリック / タップで設置。壁・床はドラッグで連続配置。建物をクリックで選択（強化・分岐・売却・開閉）
- Tab ジャンル切替、1〜9・Q/W/E 建築選択、S 売却、U 強化、Space ウェーブ開始/早回し、P 一時停止、Z 元に戻す、Esc 解除
- 設置プレビュー中は「置いた後の経路」が白い点線で、支援系は効果範囲と対象の塔が強調表示される
- ゲームオーバー時は「このウェーブからやり直す」で直前のウェーブ開始前に戻れる

## Railway デプロイ

- GitHub の main に push → Railway がそのままビルド・起動する（連携済み）
- Start Command: `npm start`、PORT は Railway 注入の `process.env.PORT`、Node は `engines.node` (>=20)

## 設計上のルール

- 状態変更は `shared/commands.js` のコマンドと `simulation.step()` だけが行う
- ゲームバランスの数値は `shared/config.js` に集約し、ロジック内にハードコードしない
- `shared/` は決定的: 同じシード・同じコマンド列なら同じ結果になる（クリティカル・気絶・賭博・変異もシードから）。リプレイ機能はこの性質に依存している
- `state.effects` は演出用の一時データ。ロジックの結果には影響しない
